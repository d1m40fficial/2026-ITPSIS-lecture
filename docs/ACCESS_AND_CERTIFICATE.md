# Доступ к лекциям и результаты самопроверки

## Что изменилось

Каталог и лекция очищены от элементов, которые не нужны студенту: деление по семестрам, подпись семестра у карточки и в шапке лекции, кнопки «Прикрепить материалы», «Настройка перед занятием» и «Начать занятие в двух окнах».

Добавлено два механизма.

## Код доступа

У каждой лекции свой код. Карточка помечена «По коду», а кнопка «Открыть» спрашивает код перед входом. Прямая ссылка на закрытую лекцию тоже приводит к этому запросу.

Коды преподаватель хранит в `config/access-codes.json`. Файл не публикуется и добавлен в `.gitignore`. Пример формы: `config/access-codes.example.json`. Список кодов в читаемом виде собирается командой `npm run list:codes` в `config/access-codes.txt`, который тоже не публикуется.

```
{
  "secret": "строка не короче 32 символов",
  "releaseCode": "МАСТЕР-КОД-НЕ-КОРОЧЕ-8-СИМВОЛОВ",
  "lectures": {
    "s07-01-support-lifecycle": ["ПРИДУМАЙТЕ-КОД-ЛЕКЦИИ"]
  }
}
```

`releaseCode` — единственный мастер-код курса. Им снимается доступ и ФИО на устройстве.

Сборка превращает коды в SHA-256 и кладёт в `public/access-codes.json` только хеши вместе с ключом подписи. Один код на лекцию даёт всем студентам группы общий доступ; несколько кодов на лекцию позволяют выдать доступ по одному на человека.

Код короче 8 символов сборка отклоняет: короткие коды перебираются по хешам.

Если `config/access-codes.json` отсутствует, лекции открываются без кода. Так ведётся разработка.

## Срок жизни доступа и смена человека

Доступ хранится в браузере неделю. Затем код запрашивается снова.

Мастер-код преподавателя (`releaseCode` в `config/access-codes.json`) снимает доступ и зафиксированное ФИО на устройстве. Кнопка «Освободить доступ» на карточке лекции спрашивает его. Сценарий: компьютер в аудитории, сегодня сдавал один человек, завтра другой — преподаватель вводит мастер-код, и следующий входит со своим кодом и вписывает своё ФИО.

Мастер-код один на весь курс и в сборку попадает только как SHA-256 хеш. Смена мастер-кода требует пересборки: `npm run compile:access`.

## Результат самопроверки для преподавателя

В окне «Самопроверка» после проверки заданий появляется блок «Результат для преподавателя». Студент один раз вводит ФИО для этой лекции и нажимает «Подписать результат». Дальше ФИО зафиксировано до снятия доступа.

Подпись — HMAC-SHA256 от ФИО, отпечатка кода лекции, баллов, времени и версии курса. Она выводится рядом с ФИО, чтобы студент показал её преподавателю на экране или снимком. Файл отчёта скачивается той же кнопкой.

### Граница защиты, честно

Ключ подписи лежит в файлах сайта. Студент с инструментами разработчика может переписать ФИО и пересчитать подпись — остановить это на статическом хостинге нечем, нужен сервер, который подписывает сам.

Что при этом работает: отпечаток кода лекции. Это первые четыре символа SHA-256 от кода, и получить отпечаток чужого кода, не зная сам код, нельзя. При **личных кодах** отпечаток однозначно указывает, чей это результат, и подменять личность не нужно.

При **общем коде на группу** отпечаток одинаков у всех, личность по нему не определить, и остаётся только ФИО — то есть ровно то, что подделывается. Если нужна настоящая привязка личности к результату, коды должны быть личными.

## Проверка на стороне преподавателя

```
npm run verify:certificate -- путь/к/отчёту.json
```

Скрипт сверяет подпись с кодами из `config/access-codes.json` и печатает ФИО, баллы и вердикт. При подмене ФИО или чужом коде выводится `ПРОВАЛ` и ненулевой код возврата.

## Сборка

`npm run build` теперь включает шаг `compile:access`, который пересобирает `public/access-codes.json` из файла преподавателя. `npm run compile:content` пересобирает курс и коды вместе.
